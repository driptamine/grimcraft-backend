# Go backend — 10 ноября 2026

Node.js-симуляция и межпроцессный мост полностью удалены по требованию
пользователя. Backend запускается и рассчитывает матчи только в Go.
Node.js используется исключительно для разработки и сборки frontend.

Go-симуляция теперь покрывает полный паритет Skirmish: движение и стойки melee/ranged,
бой, строители и строительство, очереди производства, пополнение с ценой/временем,
апгрейды гранат/плазмы, экономика и доход точек, захват и listening posts, исследования,
снос, транспорт/авиация (как подвижные юниты), определение победителя и снапшоты schema 2
(entities/players/winner). Неизвестные команды по-прежнему отклоняются явно.

Ниже сохранён исторический аудит предыдущего состояния.

Обновление после первоначального аудита: подключены HTTP-лобби и WebSocket к
интерфейсу Multiplayer, серверные roster/host/start, выбор фракции, компьютеры,
создание ECS-бойцов из Snapshot, соответствие сетевых и локальных ID,

больше не отражают текущую реализацию. Симуляция Go всё ещё упрощённая —
перенос проходимости/A*, экономики, строительства и полного боя остаётся.

## Минимальные исправления для подключения

В [cmd/server/main.go](cmd/server/main.go) заменена генерация локального
сертификата RSA с годовым сроком на ECDSA P-256 со сроком 13 дней.
Старый сертификат приводил к CERTIFICATE_VERIFY_FAILED в Chrome.
При запуске проверяются тип ключа, срок и оставшееся время; неподходящий
сертификат заменяется. Действующий сертификат переиспользуется.
Исправлен также вывод URL при `--http 127.0.0.1:8080 --wt 127.0.0.1:4433`.
Добавлены [тесты генерации и проверки сертификата](cmd/server/main_test.go).
Требования браузера: [WebTransport, certificate hashes](https://www.w3.org/TR/webtransport/#dom-webtransportoptions-servercertificatehashes).

Локальный сервер оставлен на:

- HTTP/WS: `http://127.0.0.1:8080`, `ws://127.0.0.1:8080/join?lobby=lobby-1`.
- WebTransport: `https://127.0.0.1:4433/grimcraft?lobby=lobby-1`.
- SHA-256 текущего сертификата:
  `d35517f77d99eb22e6f30f902e052762a96e2d1529eacacdbf31d4a3fa3206c7`.

В клиенте остался старый встроенный fingerprint. Для этой проверки новый введён
в поля подключения программно; постоянная конфигурация клиента не менялась.
После обновления сертификата нужно брать новый hash из вывода сервера.

Go отсутствовал в PATH. Для проверки скачан официальный Go 1.27.3, проверен SHA-256,
распакован в `/tmp/grimcraft-go-toolchain`. Запущен собранный `/tmp/grimcraft-go-server`.
Это временные пути, для постоянной разработки требуется установленный Go.

## Что перенести из актуальной игры

### Карта и движение

Сейчас сервер двигает по прямой со скоростью 6, не загружает выбранную карту,
проходимость или реальные стартовые позиции. Имя Alvarus в лобби пока только метка.

Нужны данные из `maps/6p_alvarus/6p_alvarus_path.json`, соответствующие правки,
позиции HQ, strategic_points/relics и стартовые составы из
[src/maps/map-layout.ts](../GrimCraft-main/src/maps/map-layout.ts).
Сервер должен использовать ту же итоговую сетку: 128×128, клетка 2 мировые единицы,
границы [-128,128), тип 2 проходим, тип 7 непроходим. Изображение
`alvarus-true-grid-scale.png` — визуальная проверка этих данных, не вход A*.
Рельеф имеет другой охват: нельзя растягивать сетку до размеров текстуры.

Перенести правила A* из [pathfinding/astar.js](../GrimCraft-main/pathfinding/astar.js)
и интеграции [astar-integrated.js](../GrimCraft-main/pathfinding/astar-integrated.js):
проходимость, диагонали, проверка отрезка шага, допустимые конечные позиции,
размеры юнитов/строй и препятствия зданий. Сервер вычисляет и проверяет путь,
клиент интерполирует движение между обновлениями.

### Бой и стойки

Сейчас у всех отрядов одинаковые характеристики и примитивный урон по первой
живой записи. AttackSoldier ошибочно трактует ID бойца как ID отряда.

Перенести характеристики фракций/юнитов/оружия из
[src/combat/stats.ts](../GrimCraft-main/src/combat/stats.ts), правила целей, дальность,
перезарядку, броню, улучшения, смерть и пополнение. Источники логики:
[squad.ts](../GrimCraft-main/src/systems/squad.ts),
[combat.ts](../GrimCraft-main/src/systems/combat.ts),
[melee-collision.ts](../GrimCraft-main/src/systems/melee-collision.ts).

Для последних изменений игры нужны:

- Assault/Ranged как серверное состояние и команда; клавиши 1/2 и кнопка вызывают её.
- Assault сближается с обычной скоростью и стреляет до фактического ближнего контакта.
- Ближние атаки по кругу 1/2/3, hit/block и чередование реакций у Guardsmen,
  Space Marine и Chaos Space Marine. Результат урона решает сервер;
  клипы `melee_damage_l/r`, `melee_block` и эффекты воспроизводит клиент по событиям.
- События атаки/попадания/смерти с ID источника, цели, оружием и серверным tick.
  Одних squad_pos/squad_facing недостаточно для эффектов и боевых анимаций.

### Строительство, экономика, точки и пополнение

В [commands.go](internal/hub/commands.go) PlaceBuilding, TrainUnit,
GrenadeUpgrade, DemolishBuilding и SpendRequisition подтверждаются без действия.
PlasmaUpgrade отсутствует. AutoReinforce меняет флаг, но автоматического цикла нет.
Reinforce мгновенный, без стоимости/времени, а мёртвые слоты не переиспользуются.
MoveBuilders/APCs/Jets направляются в симуляцию обычных отрядов.

Нужны отдельные сущности строителей, зданий, транспорта и авиации; стоимость,

Захват strategic_points/relics должен менять серверного владельца и доход.
Событие установки знамени/завершения захвата нужно передавать клиенту для
синхронного показа banner_rod, зелёного кольца и скрытия полосы прогресса.

## Разделение ответственности и порядок интеграции

Сервер: позиции, пути, владельцы, HP/урон, стойки, ресурсы, захват, производство,
лимиты и результат матча. Клиент: ввод, UI, интерполяция, модели, анимации и эффекты.
GLB, PNG и сотни мегабайт R2 на сервер переносить не нужно. Общие числовые данные
юнитов/оружия/карт лучше экспортировать в версионированный JSON и читать с обеих
сторон, чтобы не поддерживать вручную две расходящиеся таблицы TS и Go.

1. Согласовать версию протокола, ID и полное стартовое состояние. Подключить реальные
   лобби/команды и сторону игрока. Результат: два клиента видят свои и чужие армии,
   перемещение и остановку; нет ложной победы при входе.
2. Загрузить Alvarus и A*. Результат: оба клиента видят одинаковый обход препятствий,
   через клетки 2 идут, через 7 не проходят.
3. Добавить ranged/melee/Assault/Ranged, HP, смерть и события эффектов.
   Результат: одинаковые попадания и потери на обоих клиентах, стрельба до контакта.
4. Добавить здания, ресурсы, захват и очереди пополнения/производства. Серверное
   подтверждение должно означать выполненное действие либо принятую очередь;
   заглушки должны явно отклоняться, пока действие не реализовано.
5. Расширить остальные фракции, авиацию/транспорт, восстановление после разрыва;
   добавить command ID/ACK, удаление сущностей и согласованное обновление ресурсов,
   HP и состояния в Delta. Сейчас полные снимки раз в секунду, Delta только позиции.

Следующий практический этап — пункты P0 и первый видимый матч из двух клиентов.
Эта проверка не переносит всю игровую симуляцию: она устраняет блокировку TLS,
доказывает работу транспорта и фиксирует конкретный объём интеграции.
